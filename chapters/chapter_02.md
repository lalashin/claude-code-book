# 챕터 2: AI에게 잘 말하는 법 — 요청의 기술

## 이 챕터에서 배울 것

챕터 1에서 우리는 Claude Code에게 "파일 하나 만들어줘"라고 말했고, 정말로 파일이 만들어지는 걸 봤습니다. 신기했죠?

그런데 막상 두 번째, 세 번째 요청을 해보면 이런 일이 생깁니다. 분명히 말은 했는데 AI가 엉뚱한 걸 만들어 놓거나, 내가 원한 것과 조금 다른 결과를 내놓는 거예요. 그럴 때 많은 분이 "내가 뭘 잘못했지?" 하고 답답해합니다.

사실 여러분이 잘못한 게 아닙니다. **말하는 방법**을 아직 안 배웠을 뿐이에요.

이 챕터를 끝까지 읽고 나면, 여러분은 같은 작업도 **한 번에 원하는 결과가 나오도록** 요청하는 법을 알게 됩니다. 비결은 딱 하나, "맥락 → 목표 → 제약" 이라는 3박자입니다. 어렵지 않아요. 천천히 같이 해봅시다.

코딩 지식은 여전히 전혀 필요 없습니다. 이 챕터의 모든 예제는 메모, 장보기 목록, 일기처럼 우리 일상의 소재로만 진행합니다.

---

## 2.1 왜 같은 요청인데 결과가 다를까?

먼저 한 가지 사실을 받아들이고 시작합시다.

**AI는 여러분의 머릿속을 들여다볼 수 없습니다.**

당연한 말 같지만, 우리는 종종 이걸 잊어버려요. 머릿속에는 분명한 그림이 있는데, 입 밖으로는 그 그림의 10%만 나가는 거예요. 나머지 90%는 "당연히 이렇게 알아듣겠지" 하고 생략해버립니다.

사람끼리는 이게 잘 통합니다. 친구에게 "그거 좀 정리해줘"라고만 해도, 친구는 우리가 어제 같이 본 그 서류 더미를 떠올리죠. 하지만 AI는 그 "어제"를 모릅니다. AI가 아는 건 오직 **여러분이 방금 입력한 글자들**뿐이에요.

> **비유하자면:** AI에게 요청하는 건 처음 만난 아르바이트생에게 일을 시키는 것과 같아요. 일은 정말 잘하는 친구지만, 우리 가게 사정은 하나도 모르는 상태죠. 그래서 "알아서 잘 해줘"보다는 "이건 이렇고, 저건 저래서, 이렇게 해줘"라고 짚어줘야 합니다.

자, 그럼 실제로 어떻게 차이가 나는지 눈으로 봅시다.

### 모호한 요청 vs 구체적인 요청

같은 일을 두 가지 방식으로 부탁해볼게요. 장보기 목록을 만드는 상황입니다.

**나쁜 요청 (모호함):**

```
장보기 목록 만들어줘
```

이렇게만 말하면 AI는 막막합니다. 무엇을 사야 하는지, 어떤 형식으로, 어디에 저장할지 하나도 모르거든요. 그래서 이런 식으로 되묻거나, 혼자 짐작해서 엉뚱한 걸 만듭니다:

```
어떤 품목을 목록에 넣을까요? 그리고 파일로 저장할까요,
아니면 화면에만 보여드릴까요? 형식도 알려주시면 좋겠어요.
```

되물어주면 그나마 다행입니다. 짐작해서 만들어버리면 다시 고쳐야 하니까요.

**좋은 요청 (구체적):**

```
이번 주말에 김치찌개를 끓일 거야. 필요한 재료를 장보기 목록으로
shopping.txt 파일에 만들어줘. 각 재료는 한 줄에 하나씩, 앞에 네모 칸([ ])을
붙여서 체크할 수 있게 해줘
```

이렇게 말하면 AI는 망설임 없이 바로 만들어냅니다:

```
김치찌개 재료로 장보기 목록을 만들어 드릴게요.

● Write(shopping.txt)
  ⎿ [ ] 돼지고기 300g
     [ ] 신김치 1/4포기
     [ ] 두부 1모
     [ ] 대파 1대
     [ ] 양파 1개
     [ ] 마늘
     [ ] 고춧가루
     [ ] 국간장

✓ 완료했어요
```

두 요청의 글자 수는 별로 차이가 안 나는데, 결과는 하늘과 땅 차이죠? 무엇이 달랐을까요?

## 2.2 마법의 3박자 — 맥락, 목표, 제약

좋은 요청에는 항상 세 가지가 들어 있습니다. 이걸 **3박자**라고 부르겠습니다. 이 챕터 내내, 그리고 앞으로 Claude Code를 쓰는 내내 이 3박자를 떠올리세요.

*요청의 3박자 — 좋은 요청에 항상 들어가는 세 가지*

| 박자 | 뜻 | 방금 예제에서는 |
|------|----|----------------|
| **맥락** | 지금 어떤 상황인가? | "이번 주말에 김치찌개를 끓일 거야" |
| **목표** | 무엇을 원하는가? | "재료를 장보기 목록으로 만들어줘" |
| **제약** | 어떤 조건·형식을 지켜야 하나? | "shopping.txt에, 한 줄에 하나씩, 네모 칸 붙여서" |

다시 한번 좋은 요청을 3박자로 색칠해서 봅시다.

```
[맥락] 이번 주말에 김치찌개를 끓일 거야.
[목표] 필요한 재료를 장보기 목록으로 shopping.txt 파일에 만들어줘.
[제약] 각 재료는 한 줄에 하나씩, 앞에 네모 칸([ ])을 붙여서 체크할 수 있게 해줘.
```

세 박자가 모두 들어가니까 AI가 헤맬 구석이 없어진 겁니다.

> **외우기 팁:** "**맥**락-**목**표-**제**약"을 줄여서 "맥-목-제"로 기억하세요. 요청을 보내기 전에 마음속으로 "맥-목-제, 다 들어갔나?" 하고 한 번 점검하는 습관을 들이면 됩니다.

*요청의 3박자가 모일수록 결과가 정확해집니다*

```
   맥락만          맥락 + 목표        맥락 + 목표 + 제약
  "정리 좀..."    "목록 만들어줘"    "shopping.txt에 체크박스로"
      │                 │                     │
      ▼                 ▼                     ▼
  ┌────────┐       ┌────────┐           ┌────────┐
  │  ???   │       │  대략   │           │  정확   │
  │ 헤맴    │       │  맞음   │           │  적중!  │
  └────────┘       └────────┘           └────────┘
```

3박자가 모두 필요한 건 아닙니다. 간단한 일은 목표만 말해도 됩니다("hello.txt 지워줘"). 하지만 결과가 자꾸 빗나간다면, 십중팔구 맥락이나 제약 중 하나를 빼먹은 겁니다.

### 실습 2-1: 나쁜 요청을 좋은 요청으로 고쳐보기

이번엔 메모를 정리하는 상황으로 연습해봅시다. 먼저 일부러 모호하게 요청해보세요.

`>` 프롬프트에 이렇게 입력하고 Enter를 누르세요:

```
메모 정리해줘
```

AI는 무엇을 정리해야 할지 몰라 이렇게 되물을 거예요:

```
어떤 메모를 정리해 드릴까요? 정리할 파일이나 내용을 알려주시면,
원하시는 형식에 맞춰 정리해 드리겠습니다.
```

이제 3박자를 모두 갖춰서 다시 요청해보세요:

```
[맥락] 오늘 회의에서 적은 할 일들이 머릿속에 뒤죽박죽이야.
[목표] 이걸 todo.txt 파일에 깔끔한 할 일 목록으로 정리해줘.
[제약] 급한 것부터 위에 오도록 순서를 정하고, 각 줄 앞에 번호를 붙여줘.
할 일은 이거야: 거래처에 메일 보내기, 점심 예약, 보고서 초안 쓰기, 책상 정리
```

> 위 예제에서 `[맥락]`, `[목표]`, `[제약]` 같은 글자는 여러분이 직접 입력할 필요 없습니다. 이해를 돕기 위해 붙인 표시일 뿐이에요. 실제로는 그냥 자연스럽게 이어서 말하면 됩니다.

이제 AI가 망설임 없이 정리해줍니다:

```
회의 할 일을 급한 순서대로 정리해 드릴게요.

● Write(todo.txt)
  ⎿ 1. 거래처에 메일 보내기
     2. 보고서 초안 쓰기
     3. 점심 예약
     4. 책상 정리

✓ 완료했어요. 급한 업무인 메일과 보고서를 위로 올렸어요.
```

스스로 해보기: 여러분의 실제 머릿속 할 일을 떠올려보세요. 그걸 "맥-목-제" 3박자로 요청해서 `my_todo.txt`로 만들어보세요. 처음엔 어색해도, 몇 번 하다 보면 자연스럽게 3박자가 입에 붙습니다.

## 2.3 한 번에 다 시키지 마세요 — 단계 나누기

3박자에 익숙해지면 이제 욕심이 생깁니다. "이왕 시키는 거 한 방에 다 시켜야지!" 하고요. 그런데 이게 함정입니다.

이런 요청을 생각해봅시다:

**나쁜 요청 (한꺼번에 다):**

```
여행 계획 폴더 만들고, 거기에 일정표랑 준비물 목록이랑 예산표 만들고,
각각 보기 좋게 정리하고, 일정은 날짜별로, 예산은 항목별 합계까지 내줘
```

AI가 이걸 못 하는 건 아닙니다. 하지만 한 번에 너무 많은 걸 시키면 두 가지 문제가 생겨요:

1. **중간에 뭐가 잘못돼도 알아차리기 어렵습니다.** 일정표는 마음에 드는데 예산표가 엉망이면, 전부 다시 시켜야 할 것 같은 막막함이 듭니다.
2. **방향을 바꾸기 어렵습니다.** "아, 일정표 보니까 예산을 다르게 짜야겠다" 싶어도, 이미 다 만들어진 뒤라 손대기 번거롭죠.

요리에 비유하면, 처음 요리하는 사람에게 "3첩 반상을 한 번에 차려줘"라고 하는 것과 같아요. 하나씩 만들면서 간을 봐야 실패가 적습니다.

> **원칙:** 큰 작업은 **작은 단계로 쪼개서** 하나씩 시키고, 각 단계가 마음에 드는지 확인한 뒤 다음으로 넘어가세요.

**좋은 요청 (단계 나누기):**

같은 여행 계획을 이렇게 나눠봅시다.

*큰 작업을 3단계로 쪼개서 하나씩 확인하며 진행*

```
1단계 ──▶ 2단계 ──▶ 3단계
폴더 만들기   일정표 만들기   예산표 만들기
   │            │             │
 확인 ✓       확인 ✓        확인 ✓
```

---

### 실습 2-2: 큰 작업을 3단계로 나눠서 시키기

**1단계 — 폴더부터 만들기**

```
부산 여행 계획을 세울 거야. 먼저 trip_busan 이라는 폴더를 만들어줘
```

```
● Bash(mkdir trip_busan)
  ⎿ (폴더 생성됨)

✓ trip_busan 폴더를 만들었어요. 다음은 무엇을 할까요?
```

폴더가 잘 만들어졌는지 확인했으면, 다음으로 넘어갑니다.

**2단계 — 일정표 만들기**

```
방금 만든 trip_busan 폴더 안에 schedule.txt 파일을 만들어줘.
1박 2일 일정이고, 날짜별로 오전·오후·저녁으로 나눠서 칸을 비워둬.
내가 나중에 채울 거야
```

```
● Write(trip_busan/schedule.txt)
  ⎿ [1일차]
       오전:
       오후:
       저녁:
     [2일차]
       오전:
       오후:
       저녁:

✓ 일정표 틀을 만들었어요.
```

여기서 잠깐 보고, 마음에 들면 마지막 단계로 갑니다.

**3단계 — 예산표 만들기**

```
같은 폴더에 budget.txt를 만들어줘. 교통비, 숙박비, 식비, 입장료, 기타 항목을
두고 각각 금액을 적을 자리를 만들어줘. 맨 아래에는 '합계' 줄도 넣어줘
```

```
● Write(trip_busan/budget.txt)
  ⎿ 교통비:
     숙박비:
     식비:
     입장료:
     기타:
     ─────────
     합계:

✓ 예산표를 만들었어요. trip_busan 폴더에 일정표와 예산표가 모두 준비됐어요.
```

어떤가요? 한 단계씩 확인하며 가니까, 중간에 마음이 바뀌어도 바로 그 단계만 고치면 됩니다. 처음엔 느려 보여도, 결국 다시 만드는 일이 줄어서 더 빠릅니다.

스스로 해보기: 여러분이 요즘 준비하는 일(이사, 시험 공부, 작은 모임 등) 하나를 골라, 폴더 만들기 → 목록 만들기 → 세부 채우기의 3단계로 쪼개 요청해보세요.

## 2.4 파일을 콕 집어 지칭하기 — `@` 멘션

지금까지는 새 파일을 만드는 요청이었습니다. 그런데 이미 있는 파일을 "이 파일 말이야" 하고 가리키고 싶을 때가 있죠. 챕터 1에서 만든 `hello.txt`를 다시 불러와봅시다.

이미 있는 파일을 가리킬 때, 그냥 이름만 말해도 AI가 대개 알아듣긴 합니다. 하지만 더 확실하고 빠른 방법이 있어요. 바로 **`@` 멘션**입니다.

요청을 입력하다가 `@`(골뱅이) 기호를 치면, Claude Code가 현재 폴더에 있는 파일 목록을 슬쩍 보여줍니다. 거기서 원하는 파일을 고르면 돼요. 카카오톡 단체방에서 `@`를 쳐서 특정 사람을 콕 집어 부르는 것과 똑같습니다.

> **왜 `@`를 쓰면 좋은가요?** 파일 이름을 직접 다 타이핑하다 보면 오타가 나기 쉽습니다. `@`로 목록에서 고르면 오타 걱정이 없고, AI도 "아, 정확히 이 파일이구나" 하고 확실하게 알아듣습니다. 특히 파일이 많은 폴더에서 진가를 발휘해요.

---

### 실습 2-3: `@`로 파일 콕 집어 부르기

챕터 1에서 만든 `hello.txt`가 있는 폴더(바탕화면)에서 Claude Code를 실행했다고 가정합니다. `>` 프롬프트에 `@`를 입력해보세요.

`@`를 치는 순간, 이런 파일 목록이 뜹니다:

```
> @
  ┌──────────────────────────┐
  │ @hello.txt               │
  │ @memo.txt                │
  │ @shopping.txt            │
  └──────────────────────────┘
  (방향키 ↑↓로 고르고 Enter로 선택)
```

방향키로 `@hello.txt`를 고르고 Enter를 누르면, 프롬프트에 `@hello.txt`가 자동으로 입력됩니다. 그 뒤에 이어서 요청을 적으세요:

```
@hello.txt 의 내용을 읽고, 끝에 "오늘도 좋은 하루!"라는 인사말을 한 줄 추가해줘
```

이제 AI는 정확히 그 파일을 읽고 수정합니다:

```
● Read(hello.txt)
  ⎿ 안녕하세요, Claude Code입니다!

● Edit(hello.txt)
  ⎿ 안녕하세요, Claude Code입니다!
     오늘도 좋은 하루!

✓ hello.txt 끝에 인사말을 추가했어요.
```

여기서 이 요청을 3박자로 다시 들여다볼까요?

```
[맥락] (@hello.txt 로 어떤 파일인지 콕 집음)
[목표] 내용을 읽고 인사말을 추가해줘
[제약] 끝에, "오늘도 좋은 하루!"라는 한 줄로
```

`@` 멘션은 3박자 중 **맥락을 가장 정확하게 전달하는 방법**입니다. "그 파일"이 아니라 "바로 이 파일"이라고 손가락으로 가리키는 셈이니까요.

> **폴더도 가리킬 수 있어요.** 파일뿐 아니라 폴더도 `@`로 멘션할 수 있습니다. 예를 들어 `@trip_busan 폴더 안에 뭐가 있는지 정리해서 보여줘` 처럼요. 폴더를 통째로 가리켜 "이 안에 있는 것들"을 다루게 할 수 있습니다.

스스로 해보기: 실습 2-1에서 만든 `todo.txt`(또는 `my_todo.txt`)를 `@`로 멘션해서, "다 끝낸 일은 줄 끝에 (완료)를 붙여줘"라고 요청해보세요.

---

## 2.5 작업 도중에 멈추고 방향 바꾸기 — Esc

AI에게 일을 시키다 보면, 결과를 보기도 전에 "어, 이게 아닌데?" 싶은 순간이 옵니다. 내가 요청을 잘못 말했거나, 말하고 나서 마음이 바뀌었거나요.

이럴 때 AI가 작업을 다 끝낼 때까지 멍하니 기다릴 필요가 없습니다. **Esc 키** 하나로 즉시 멈출 수 있어요.

`Esc`는 키보드 맨 왼쪽 위에 있는 키입니다. Claude Code가 한창 작업하는 중에 이 키를 누르면, AI가 하던 일을 그 자리에서 멈춥니다. 자동차로 치면 브레이크예요. 언제든 밟을 수 있다는 걸 알면, 마음 놓고 운전할 수 있죠.

> **Esc는 안전장치입니다.** "혹시 AI가 이상한 짓을 하면 어쩌지?" 하는 걱정 때문에 요청을 머뭇거릴 필요가 없어요. 무슨 일이 벌어지는 게 보이면 그냥 Esc를 누르면 됩니다. 멈추는 건 언제나 여러분 손에 있습니다.

---

### 실습 2-4: 작업 멈추고 다시 시키기

일기 쓰기를 도와달라고 하는 상황을 가정해봅시다. 이렇게 요청했다고 해볼게요:

```
diary.txt 파일을 만들고 오늘 하루를 일기로 써줘
```

그런데 AI가 일기를 쓰기 시작하는 걸 보니, 문득 이런 생각이 듭니다. "잠깐, 내 하루가 어땠는지도 안 알려줬는데 AI가 내 일기를 어떻게 써? 이건 내가 직접 써야지!"

이럴 때 흐름은 이렇습니다:

```
Step 1: AI가 일기를 작성하기 시작함 (화면에 글자가 만들어지는 중)
          ↓
Step 2: 키보드에서 [Esc] 키를 누름
          ↓
Step 3: AI가 작업을 멈춤
```

Esc를 누르면 이런 화면이 나옵니다:

```
⏸ 작업을 중단했어요. 무엇을 다시 도와드릴까요?

>
```

이제 방향을 바꿔서 다시 요청하면 됩니다. 이번엔 제대로 3박자를 갖춰서요:

```
[맥락] 일기는 내가 직접 쓸 거야. 오늘은 비가 와서 집에서 책을 읽었어.
[목표] diary.txt 파일에 일기 쓸 틀만 만들어줘.
[제약] 맨 위에 오늘 날짜, 그 아래 '날씨:', '오늘 있었던 일:', '기분:' 항목만
비워서 만들어줘. 내용은 내가 채울게
```

```
● Write(diary.txt)
  ⎿ 2026년 6월 15일
     날씨:
     오늘 있었던 일:
     기분:

✓ 일기 틀을 만들었어요. 빈칸은 직접 채워보세요!
```

처음 요청이 빗나갔어도 전혀 문제없죠? **멈추고, 고쳐 말하면** 됩니다. 이게 AI와 대화하는 자연스러운 리듬입니다. 한 번에 완벽할 필요가 없어요.

> **참고:** 멈춘 다음에 "방금 만든 거 지워줘"라고 하면 되돌릴 수도 있습니다. 파일을 안전하게 되돌리고 관리하는 방법은 챕터 3에서 자세히 다룹니다.

---

## 2.6 "모르겠으면 물어봐" — AI에게 되묻게 하기

지금까지 우리는 "어떻게 잘 말할까"를 고민했습니다. 그런데 마지막으로, 정말 강력한 비결이 하나 더 있어요. 바로 **AI에게 먼저 물어보게 하는 것**입니다.

우리가 아무리 3박자를 갖춰도, 가끔은 빠뜨리는 게 생깁니다. 내가 뭘 빠뜨렸는지조차 모를 때도 있죠. 이럴 때 AI가 알아서 짐작하고 일을 진행해버리면, 결과가 어긋나기 쉽습니다.

그래서 요청 끝에 이 한 문장을 붙이는 습관을 들이세요:

```
...애매하거나 빠진 정보가 있으면, 먼저 나한테 물어봐줘
```

이 한마디가 AI의 태도를 바꿉니다. 짐작해서 밀어붙이는 대신, **확인하고 시작**하게 만들거든요.

---

### 실습 2-5: AI가 먼저 묻게 만들기

가계부를 만들어달라고 해봅시다. 일부러 정보를 좀 빼고, 대신 "물어봐줘"를 붙여보겠습니다.

**되묻기 유도 없이 (짐작해서 진행):**

```
가계부 파일 만들어줘
```

```
● Write(budget.txt)
  ⎿ 날짜 | 항목 | 금액 | 메모

✓ 가계부를 만들었어요.
```

AI가 알아서 만들긴 했는데, 내가 원한 형식이 맞을까요? 월별로 나누고 싶었을 수도, 수입·지출을 구분하고 싶었을 수도 있는데 AI는 그냥 짐작했습니다.

**되묻기를 유도하면 (확인하고 진행):**

```
가계부 파일을 만들고 싶어. 그런데 형식을 어떻게 할지 아직 안 정했어.
좋은 가계부 형식을 제안하기 전에, 내 상황을 알아야 할 것 같으면 먼저 물어봐줘
```

이제 AI는 바로 만들지 않고, 똑똑한 질문을 던집니다:

```
가계부를 잘 만들기 위해 몇 가지만 여쭤볼게요.

1. 기록 단위는 어떻게 할까요? (매일 / 매주 / 매월)
2. 수입과 지출을 따로 나눠서 적고 싶으세요?
3. 카테고리(식비, 교통비 등)를 미리 정해 둘까요?

알려주시면 딱 맞는 형식으로 만들어 드릴게요.
```

이 질문들에 답하면, AI는 정확히 내 상황에 맞는 가계부를 만들어줍니다. 짐작으로 만든 뒤 고치는 것보다 훨씬 빠르고 정확하죠.

> **이게 왜 강력한가요?** 사실 AI는 우리보다 "무엇을 더 물어봐야 좋은 결과가 나오는지" 잘 알 때가 많습니다. 우리가 미처 생각 못 한 부분을 짚어주거든요. "모르겠으면 물어봐"는 그 능력을 끌어내는 스위치입니다.

스스로 해보기: 여러분이 만들고 싶은 무언가(독서 기록장, 운동 일지, 식단표 등)를 떠올려보세요. 형식을 정하지 말고 "내 상황을 먼저 물어봐줘"라고 요청한 뒤, AI의 질문에 답하며 만들어보세요.

---

## 2.7 요청 체크리스트

요청을 보내기 전에, 아래 다섯 가지를 마음속으로 점검해보세요. 처음엔 하나씩 확인하다가, 익숙해지면 자연스럽게 몸에 뱁니다.

> **📋 요청 체크리스트 — 보내기 전에 5초만 점검!**
>
> 1. **맥락**을 줬는가? → 지금 어떤 상황인지 한 문장이라도 설명했나?
> 2. **목표**가 분명한가? → 무엇을 만들거나 바꾸고 싶은지 명확한가?
> 3. **제약**을 말했는가? → 형식, 파일명, 순서 등 지켜야 할 조건을 알려줬나?
> 4. 너무 **한꺼번에** 시키고 있지 않은가? → 큰일이면 단계로 쪼갰나?
> 5. 애매하면 **물어봐 달라**고 했는가? → "빠진 정보 있으면 먼저 물어봐줘"를 붙였나?

이 다섯 가지를 다 채울 필요는 없습니다. 간단한 일은 2번(목표)만으로 충분해요. 하지만 **결과가 자꾸 빗나간다면**, 이 체크리스트를 위에서부터 훑어보세요. 빠뜨린 박자가 분명히 보일 겁니다.

---

## 이 챕터에서 배운 것

- AI는 내 머릿속을 모른다 — 말로 표현한 것만 알아듣는다 (처음 만난 아르바이트생 비유)
- 좋은 요청의 비결은 **맥락 → 목표 → 제약**의 "3박자"다 ("맥-목-제"로 기억)
- 같은 작업도 3박자를 갖추면 한 번에 원하는 결과가 나온다
- 큰 작업은 **한꺼번에 시키지 말고 단계로 쪼개** 하나씩 확인하며 진행한다
- `@` 멘션으로 파일·폴더를 **콕 집어** 가리키면 오타도 없고 맥락도 정확하다
- 작업 도중 방향이 틀어지면 **Esc**로 즉시 멈추고 다시 요청하면 된다 (안전장치)
- 요청 끝에 **"애매하면 먼저 물어봐줘"**를 붙이면 AI가 짐작 대신 확인하고 시작한다
- 헷갈릴 땐 **요청 체크리스트** 5문항을 위에서부터 점검한다

## 다음 챕터 예고

다음 챕터에서는 그 대화로 **진짜 내 컴퓨터의 파일과 폴더를 본격적으로 다뤄봅니다.** 어질러진 다운로드 폴더를 한 번에 정리하고, 파일 수십 개의 이름을 한꺼번에 바꾸고, 여러 파일을 합치거나 나누는 일을 자연어 대화만으로 끝내볼 거예요.

"내 소중한 파일이 망가지면 어쩌지?" 하는 걱정도 함께 풀어드립니다. AI가 일을 저지르기 전에 미리 보여주고 허락을 구하는 **안전장치**들이 있거든요. 이제 정말 손에 잡히는 작업을 시작해봅시다!
